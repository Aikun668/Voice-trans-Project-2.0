# 最后核对与无参考测试性训练

日期：2026-11-14。用户已明确授权：最后核对通过后直接测试性训练、重新输入验证并交付原音、原唱参考和训练模型处理音频；若核对失败，调查替代方法。技术路线由 Agent 判断，无须再确认实施细节。

## 规则

### 硬性格式
1. 原始素材、上轮清洗和旧模型全部只读；本轮所有产物留在本实验，每阶段新建子目录并拒绝覆盖。
2. 不安装或升级已有环境的依赖，不提交或推送 Git。复用主项目现成环境和模块，记录版本和来源。
3. 保留完整输入样本数、时长和唱词。整体升调默认关闭，不把原唱音区强加给用户。

### 内容要求
4. 最后核对增加独立发音内容特征对齐，与上轮 MFCC 映射交叉比较；用两种音高估计检查不稳定及八度错误。候选不因文件校验通过就自动变成音高真值。
5. 核对门槛：足够多的不同歌曲、有效正常帧和偏音帧；配对不复用、训练/验证/测试歌曲不交叉；不确定的时间和音高留作掩码并记录。不要求全体候选通过才能对合格子集试训。
6. 处理录音时输入只有清唱及其自身提取的特征；原唱、答案曲线、人工跑调范围不得进入模型输入。专业版仅作训练监督和事后比较，不设置参考修音回退。
7. 首轮可采用 PyTorch 标准 GRU 序列模块的小模型，学习前后音高上下文与修正；不是旧参考差回归器，也不冒充 MusicBERT 或论文复现。最终方案按核对结果调整。
8. 普通正确演唱必须有保留样例；记录零修改、简单规则与模型在验证/测试歌曲上的差别，不能靠全零输出或只报成功片段宣称效果。
9. 保存权重后在新进程中重新载入、只输入本人完整清唱再处理。保存模型输入字段、权重哈希、预测曲线和实际应用曲线；做零预测旁路及参考不可访问检查。

### 提交要求
10. 交付一首歌的一条完整清唱的原音、对应原唱参考、模型版，以及简洁试听入口；如需额外诊断版本，总量遵守既有试听负担。
11. 每个导出音频检查样本数、采样率、NaN、削波、FFmpeg 实测 LUFS/真峰值、音高跟随与浊音重合，记录源哈希和对原音改动。工程失败不作为通过版交付。
12. Agent 不能听音；工程结果与用户听感分开。测试性训练完成不等于中文修准、自然或无电音已经验收。

## 方案选择与代价

- 首选：独立内容对齐核验合格子集，输入本身音高上下文的小型序列修正模型。现有 CPU 可测试，优先验证任务与数据是否成立。
- 备选：若真人标签缺少有效偏音，使用专业版保留样例及显式标明的合成偏音补练，以真人候选作独立检查；不能只报合成成绩。
- 暂不首选：从头训练整段波形生成器，或默认恢复旧 NeuralSVB 美化权重；本机 CPU、已有重建问题和有限域数据不足以支撑优先投入。更换渲染器由原音重建及已知移调检查决定。
- 首次核对成功指获得可做探索训练的技术监督子集，不宣称人工逐音真值。原唱目标存在的不确定性写入报告。
