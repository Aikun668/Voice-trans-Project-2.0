# 项目分区整理计划

**Goal:** 把过期入口改为真实现状，明确主次线、资产和历史的去向。

**Architecture:** 主项目 ROADMAP 管路线；FILE_INDEX 管找文件；分区说明只解释划分。两个旧工作树只增加现行入口指向，保留各自历史正文及独有资产。

**Spec:** rules.md；本轮 feedback.md；docs/版本与引用核查_2026-11-14.md；已实际读取的次线对话及 MusicBERT REPORT/verification/evaluation。

**Tech Stack:** Markdown、CSV、JSON；现有 Python 标准库只做清单和核验。

## 执行步骤

- [x] 读核查、主次线授权和实际产物，识别入口过期、事实错误及运行依赖。
- [x] 留存文档快照和受保护文件指纹。
- [x] 更新主项目 README、AGENTS、ROADMAP、文件索引及日志；给旧阶段计划加归档提示。
- [x] 给两个旧工作树的入口加主项目指向；撤销旧交接中的重复17对待办。
- [x] 按实际角色登记全部实验、17对来源及已知运行依赖；逐项落实或说明不采纳的核查建议。
- [x] 核对链接、源哈希、保护文件及目录位置；写简短说明和规则自检。

## 检查重点

- 不把“最新次线”写成“主线已换为 MusicBERT”。
- 不把“17对切口已确认”写成“17对逐帧目标音已验收”。
- 不因逻辑归档而搬走 still-imported 旧代码或原唱副本。
- 两个旧工作树的历史 ROADMAP 不再与主项目争夺现行依据。
- 失败结果和待试听状态分别记录，不重写旧轮验证为新通过。

本轮由当前对话直接执行文档整理；不提交 Git、不另开工作树、不启动模型工作。
