## 1. 项目一句话与需求边界

**一句话**：输入一段手机录的中文清唱，输出同一个人"唱得更好听"的清唱。F1 管音色（饱满、有力、悦耳、不刺耳），F2 管音高（不跑调、稳）。两者组合要让人一听就觉得"同一个人唱得更好了"。

| 项 | 需求原件（PoC v1.2） | 当前状态 / 已确认的调整 |
|---|---|---|
| 周期 | 一周初步验证可行性 | Jade 转述（10-27 会话）：老师说若接下项目，周期可能半年到一年。**本周仍需交一个小范围验证 demo** |
| F1 | 饱满度、柔和度、悦耳度；刺耳、齿音、音量不均；保留原声 | Jade 的核心诉求已收敛为"**声带发声能量 / 力度感**"，不嗲、不蔫（§2） |

## 3. 已证实的关键结论（证据在括号中的目录）

### 3.1 F1：薄音的成因与杠杆

**《我们的歌》对照**（experiments/WOMENDE_FOCUS_2026-11-03_v001，只统计响段浊音帧）：

| 指标 | 薄音版 | 本人正常版 | 王力宏 |
|---|---|---|---|
| F0 中位 | **136 Hz** | 158 Hz | 160 Hz |
| alpha ratio（1–5 kHz vs 50 Hz–1 kHz） | **−27.4 dB** | −16.1 | −16.8~−17.7 |
| H1−A3 | **37.1 dB** | 24.4 | 26.4~27.4 |
| H1−H2（气声） | 4.6 | 2.45 | 6.5~6.8 |

- 薄音版与正常版是同一段旋律，**整体低约 310 音分**（约 3 个半音）。
- 声源差距体现在高次谐波少 11–13 dB；**气声不是问题**。
- 只在元音谐波上补 15 dB（差距缩小约 2/3）：**听不出区别**。
- 升调 310 音分：**明显更有力**。

**四首薄音版与正常版的 F0**（test_dataset/f1_dataset_v2/catalog.csv）：

| 歌 | 薄音版 | 正常版 | 结论 |
|---|---|---|---|
| 我们的歌 | 136.4 | 158.5 | 唱低约 2.6 个半音 → **升调杠杆适用** |
| 因为刚好遇见你 | 201.7 | 226.2（"原版"） | 唱低约 2 个半音 → 可能适用 |
| 平凡之路 | 175.9 | 171.7 | 同调 → 升调**不适用**，需要别的手段 |
| 雅俗共赏 | 187.1 | 187.7 | 同调 → 升调**不适用** |

> 推论（待验证）：薄音 = ①音区偏低（部分录音）+ ②声带用力不足（全部录音）。①可以用升调解决；②效果器基本到顶（见 3.3），长期要靠 AI 自转换（§5 P2）。

**空旷 / 录音机感的成因**（experiments/DEMO_2026-11-02_v002、v003 README）：

- 不是长混响：WPE 去混响在常规参数下只去掉不到 1 dB。
- **原因 A：音色比例**。手机录音和录音室人声相比，125–200 Hz 多 7–10 dB，2–3 kHz 少约 18 dB。
- **原因 B：压缩器在字尾回弹**。快释放压缩让每个字结束后的房间余音相对歌声抬高 +6~+10 dB（响段只高 +1 dB）。
  - 改法：慢释放 350 ms + 字尾守护（字尾最多 +3 dB）后，实测降到 +2.6~+3.2 dB。
  - 这个版本（demo v003 的 A/B）**还没有 Jade 的反馈**。11-03 的升调版仍"有一点点空旷"，所以字尾守护仍需要。

**守护规则**：EQ 不允许削 250 Hz 以下。这是 Jade 的基频区，削了会让声音更薄（demo v002 实测，削后 Praat 浊音帧丢失到 0.895）。

### 3.2 F2：已证实的事实

1. **无参考修音的上限**：贴到最近半音，最大改动 ±50 音分。
2. **Jade 的听辨阈值**：单音 98 / 199 音分能辨；句内短音 103 音分不能辨；句内长音 247 音分能辨。所以无参考修音对 Jade 不可感知（f2/PHASE2_NOTES.md）。
3. **旧 P3b–P3e 有配对 bug**：按相对位置配音符，目标与参考长度不同时会配错（0–2 秒配到了原唱 1.9–8 秒）。**P3b–P3e 的输出不能当证据。**
4. **重新对齐后**（f2/poc_phase4_realign.py）：《因为刚好遇见你》比李玉刚高约 145–156 音分，全程一致；扣除后 25 个音全在 ±85 音分以内，**基本不跑调**。
5. **自参考对齐失败**：用本人 severe 版对 normal 版做对齐，音高和 MFCC 两种方法都失败。**对齐到全曲原唱人声**才成功（shige_* 实为《自由飞翔》，zuixuan_* 为《最炫民族风》）。
6. **phase4b**：只在被修的音上拼接重合成，其余部分原样保留；平滑移调；同向偏差成组。
7. **phase4c**：处理拖音。两阶段对齐（先定位区间，再在区间内允许"保持"步）；按事件和 0.24 秒块修；相邻修正连续衔接；两种对齐结果不一致不修；短于 0.25 秒不修。
   - 偏差 >100 音分的帧占比：最炫·轻度 30%→25%，自由飞翔·严重 21%→17%，最炫·严重 20%→18%。**未获反馈。**
8. **电音来源（推断）**：① 整段 PSOLA 重合成；② 修正曲线在相邻音之间来回跳；③ 短音大幅修正。①②③在 4b/4c 中已分别处理。

### 3.3 已证伪 / 已否决的方向（不要再试）

| 方向 | 证据 | 结论 |
|---|---|---|
| 单项 EQ（低架、高架、峰值，多档） | F1-EXP-001~007 | 只会更亮或更响，不更饱满 |
| tanh / Distortion 饱和 | EXP-004~006、F1_S1_density | 变闷 |
| 并联谐波激励（V2 能量链） | DEMO v001 | "录音机" |

| 谐波结构对齐、频谱包络移植单用 | EXP-015/016 | 对齐到 97–99% 仍只是"微弱可辨" |
| 元音谐波倾斜（只补高次谐波） | WOMENDE_FOCUS v001 C1 | **听不出区别** |
| 混响、双叠 | 对齐页 Q6/Q7 | Jade 否决 |
| 匹配录音室频谱 EQ（V3） | DEMO v002 | 只有雅俗共赏被选中，其余仍空旷 |

## 4. 目标架构（处理链）

```
原始清唱 WAV
  │
  ├─[F2-K 音区开关]  整体升 / 降 N 个半音（默认关；Jade 已确认做成独立开关，归 F2 音高侧）
  │     复用 f2/poc_phase1.shift_uniform（Praat PSOLA，保共振峰）
  │
  ├─[F2-P 跑调修正]  有参考：f2/poc_phase4c.py；无参考：待研究（§5 P3）
  │     只在修正处重合成，其余采样原样
  │
  ├─[F1-T 音色链]    A = V1 EQ + 慢释放压缩 + 字尾守护 + 安静段复原 + 句间降噪
  │     （experiments/F1_demo_chain_2026-11-02_v003/run.py chain_dry）
  │     可选：共振峰上移（formant_shift.py，S45 原样复刻）
  │
  ├─[F1-AI 自转换]   （P2 研究项）用本人"有力"录音训练的歌声转换模型
  │
  └─[母带]           -13 LUFS，前视真峰值限幅 ≤ -1 dBTP
        （experiments/F1_demo_chain_2026-11-02_v001/run.py master / tp_limit）
```

- **接口**（沿用契约 v1.0）：每个模块输入输出都是单声道 WAV；样本数不变；不改节奏。
- **F1 不改音高**：升调只出现在 F2-K。
- **默认顺序**：F2-K → F2-P → F1 → 母带。Jade 听感优先，顺序可以调整。
- 每个模块都必须能单独旁路，方便定位问题出在哪一级。

### P2 · F1 AI 自转换可行性（约 2–6 周，Jade 已授权"可用本人声音训练"）

**为什么做**：平凡之路、雅俗共赏的薄音版和正常版同调，升调用不上；效果器补谐波听不出来。"声带用力"在声源层面，需要模型把"薄唱法"重新渲染成"本人有力唱法"的音色。

**方案**：歌声转换（SVC）"自己转自己"。训练数据只用 Jade 的有力 / 正常录音；推理时输入薄音版，保留原 F0（不改音高）和原时长。

**步骤**：

1. **选型调研**（不写代码）：按 §7.4 "复用优先"，核对候选项目的许可证、CPU 可行性、最少数据量、是否支持保留 F0、中文歌声样例。
   - 候选（**全部未核验**，接手时逐个确认）：RVC（Retrieval-based-Voice-Conversion-WebUI）、so-vits-svc-fork、DDSP-SVC、Seed-VC。
   - 产出：选型卡，最多两个候选。
2. **算力**：本机**没有 NVIDIA GPU**，torch 为 CPU 版。训练很可能需要 GPU，要**问 Jade 或老师**能否提供 GPU / 云算力。CPU 只够推理和极小规模试训。
3. **数据**：请 Jade 用同一部手机、同一个安静房间，录 10–30 分钟"正常 / 有力"清唱（多首歌、覆盖高低音区）。另出一份录音说明给 Jade。
   - 已有素材（4 首正常版 + my_singing 的 normal 版）约 2 分钟，只够冒烟测试。
4. **冒烟测试**：先用现有约 2 分钟数据跑通流程（预期音质差），确认没有工程障碍再请 Jade 录数据。
5. **正式测试**：在《我们的歌》《平凡之路》薄音版上出成品，按 §7 试听协议。
6. **否决项**：沙哑、鼻音、跳变、不像本人、咬字变化（都是 NeuralSVB 的失败点）。

- 通过：至少 2 首中 Jade 认为"更有力且像本人"，并且好于 P0 的效果器版。
- 停止：一个候选经过 2 轮仍有否决项，就换候选；两个候选都失败，就回到效果器 + 升调方案，并在 §12 记录。

### P3 · F2 成熟化（约 1–3 个月，可与 P2 并行）

1. **先拿反馈**：phase4c 三条跑调录音的 Jade 反馈（demo v003 未听）。
2. **拖音与表现性唱法**：区分"故意的滑音 / 吼 / 变口型"和"走音"。当前策略是不确定就不修（宁可漏修，不要电音）。可以研究：
   - 用原唱的音符边界（需要更稳的原唱音符分割）；
   - 让 Jade 在页面上标"这几秒是故意的"，作为监督信息。
3. **音区开关 F2-K**：做成 CLI 参数和可选自动建议（与本人正常版或原唱比较调差）。默认关。
4. **无参考模式**（回到需求原意）：在 Jade 不熟悉的歌或没有原唱时，用旋律先验（调式推断、音阶吸附但只修大于阈值的长音）。阈值依据 §3.2 的听辨数据。
5. **合成器质量**：PSOLA 在大幅修正时会有伪影。可以评估 WORLD / 神经声码器重合成（复用现成实现）。
6. **更多参考歌曲**：平凡之路、雅俗共赏的原唱人声已有（test_dataset/reference/vocals），但还没有对齐。

- 通过：至少 2 首真正有跑调的录音上，Jade 判定"修回来了、自然"。

### P4 · 产品化与泛化（约 3–12 个月）

- 统一入口：`pipeline` CLI，读一个 YAML 配置，依次调用 F2-K / F2-P / F1-T / F1-AI / 母带，每级可旁路，输出 QA 报告和试听页。可参考 f1_adaptive_v0 的"特征 → 规则 → 参数 JSON"框架。
- 自动决策：根据特征（F0 相对本人常用音区、alpha ratio、字尾抬升等）推荐开哪些模块、多大强度。**每条规则都要有 Jade 判定作依据。**
- 泛化：GTSinger 男女声、web_singing、其他人的录音（需要获得授权）。不同人的目标不同，要另行确认需求。
- 客观指标与听感的相关性：积累 Jade 的判定数据（§11 反馈总表），检验哪些指标能预测"更好"。不要提前用指标代替听感。
- 不在范围内，除非老师要求：实时、硬件、伴奏、混响、情感增强。

## 7. 工作方式（替代旧 AGENTS.md 的流程规则）

### 7.1 每轮流程

1. **读最新反馈**，原话存档（试听页导出的文字原样保存到该轮目录的 `feedback.md`）。
2. **先诊断再动手**：说清"哪里不对、可能为什么"，最好有测量证据。试过的方向先查 §3.3。
3. **一轮一首歌**（Jade 指定或默认上次那首），最多 3–4 个处理版。可以同时改多个参数，但每个版本要有明确的目的（如"试极限""解决空旷"）。
4. **工程检查全部通过**（§8.2）才放进试听页。
5. **试听页**交给 Jade，等反馈。
6. **更新** §11 / §12。

### 7.2 试听页格式（沿用已验证好用的形式）

- 单个 HTML，放在该轮目录的 `index.html`；音频放 `audio/`。
- **同组只放一个播放器**，按钮切换时从当前位置无缝接着播。
- 所有版本**标明名字**，不做盲听（沿用旧约定，Jade 不要求盲听）。每个按钮附一句"做了什么"的白话说明。
- 必有"① 原音·同样响"作为锚点，用来区分"只是更响"和"真的变好"。
- 题目用日常词，给选项，加一个补充文本框；底部"生成答案"按钮把结果导出成文字。
- 顶部写清：怎么听（耳机、固定音量）、响度标准、"Agent 不能听音"的声明。
- 控制总听音时长 ≤ 10 分钟。

### 7.3 响度规则

- **成品轮**（默认）：所有版本做到 -13 LUFS / ≤ -1 dBTP，包括原音锚点。
- **诊断轮**（只问"变化来自哪"）：等响（如 -18.5 LUFS），只施加固定增益，页面上写明。
- 不允许用隐藏的限幅器改变比较条件；限幅要写在说明里。

### 7.4 复用优先、诚实记录

- 先找现成模块（Pedalboard、Praat / parselmouth、FFmpeg、开源模型）。记录项目地址、版本、许可证、具体接口、做了哪些必要适配。
- 自写 DSP 只限：适配层、分析测量、拼接 / 守护逻辑。
- 记录必须分开 **technical_pass**（工程）和 **pending_jade / Jade 判定**（听感）。Agent 不能听音，必须明说；不得把测量变化写成"变好听"。

### 7.5 何时放弃一个杠杆

- 同一杠杆接近上限强度时连续两轮"听不出区别"，就判定到顶，写入 §3.3，换杠杆。
- 有否决项（电音、空旷、闷、不像本人）的版本：定位原因，最多做一次针对性修订；仍然失败就停用该版本。
- 不允许为了"有变化"放宽工程门槛。

### 7.6 子 Agent

- 一律 `model: haiku`、`effort: high`。
- 适合交给子 Agent 的：抽取 / 复刻已有代码并逐样本验证、批量测量、选型调研、文档整理。
- 不适合的：需要连续判断的音频调参（留在总督手里）。
- 给子 Agent 的提示要写清：不改现有文件、输出到哪个新目录、怎么验证、回复限多少字。

## 8. 工程规范与已知坑

### 8.1 环境（全部 Windows + Git Bash；**不要往已有环境里装包**，要新依赖就新建环境，或放进实验目录的 vendor/）

| 环境 | Python | 用途 | 关键包 |
|---|---|---|---|
| .venv-f1-adaptive | 3.12.7 | F1 链、母带、测量 | pedalboard 0.9.26、librosa 0.11、scipy、soundfile |
| .venv-f2 | 3.12.7 | 音高分析与修正 | parselmouth 0.4.7、numpy 2.5.4（**没有 scipy**） |
| .venv-sep | 3.12.7 | Demucs 人声分离 | torch 2.15.0+cpu、demucs |
| .venv-tools | 3.12.7 | 下载 / 转码 | yt-dlp、imageio-ffmpeg |
| .venv-f1 | 3.12.7 | 旧 F1 | 历史 |
| experiments/F1_route1_smule_v001/.venv | 3.10 | Smule | 历史 |

FFmpeg 在 PATH 中（WinGet）。**本机没有 NVIDIA GPU。**

### 8.2 每个输出文件的工程检查

- 样本数与源一致；采样率不变；无削波；无 NaN。
- 响度和真峰值用 FFmpeg ebur128 读回实测（不信任内部计算）。
- 音高：处理版对原音的逐帧中位偏差（预期 ≈0，F2 / 升调除外），以及浊音帧重合率（掉到 0.95 以下要查原因）。
- F1：字尾抬升（v003 `lift_stats`）、齿音段指标（v002 `qa_extra.py`）、句间底噪。
- F2：实际移调与目标的差（应 <5 音分）；修正段外与原音逐样本一致（拼接区除外）。
- 源文件哈希在处理前后一致。

### 8.3 文件安全

- 原始素材（test_dataset/）只读。
- 每次实验新建目录：`experiments/<主题>_<YYYY-MM-DD>_vNNN/`；脚本遇到已存在的输出目录要拒绝覆盖。
- 作废的中间结果移到 `_superseded_<日期>/` 子目录，不删除。
- 未经要求不提交、不推送 Git。

### 8.4 已踩过的坑

1. Pedalboard `Limiter` 在瞬态上真峰值会越界（实测 +0.5 dBTP）→ 母带用 v001 的 `tp_limit`（4 倍过采样前视）。
2. `.venv-f1-adaptive` 里 `librosa.pyin` 会触发 numba 段错误 → 音高一律用 Praat（.venv-f2）。
3. `.venv-f2` 没有 scipy → 用 numpy 实现的滤波（见 poc_phase4c.py）。
4. Git Bash 的 `/tmp` 和 Windows Python 的 `/tmp` 不是同一个目录 → 中间文件放实验目录。
5. 各实验目录都有 `run.py` / `build_demo.py`，`sys.path` 导入会撞名 → 用 `importlib.util.spec_from_file_location` 按路径加载。
6. Bash 里花括号展开会被转义（`mkdir -p a/{b,c}` 会建出字面目录）→ 分开写。
7. 修正后的音频要用"同一增益"还原到原音电平，再进 F1 链（F1 压缩门限是绝对电平）。
8. 共振峰移位（formant_shift.py）单点增益可达 15–16 dB，有伪影风险；Praat 音高 p95 偏差会变大（测量干扰，非真实改音高）。
9. phase4c 的"保持步"不能在全曲搜索，否则会退化（落到 239 秒、调差 −486）→ 必须先用无保持的 DTW 定位区间。
10. Demucs 分离的原唱人声带混响和制作处理，只能作方向参考。
11. `test_dataset/my_singing/shige_*` 的歌实为《自由飞翔》（凤凰传奇），文件名沿用旧登记，不要改原文件名。
