# 一起理解我们的歌声项目

我们想做的事情很简单：录一段自己的清唱，处理之后，声音还是自己，唱得更准，也更有自己想要的力度。目前我们准备先拿“修正跑调”做一个小实验，学习怎么整理数据、训练模型、听结果和解决问题。我们两个人都在边做边学。

## 我们之前是怎么做的

一开始为了方便推进，我们把问题分成两块。F1 关注声音听起来够不够饱满、有力，F2 关注音唱得准不准。这样两个人可以各自研究一个问题，再讨论怎么把结果放到一起。

刚开始我们准备了几种清唱录音，比如正常唱的版本、稍微跑调的版本和跑调更明显的版本。这样做是为了比较不同情况，看看处理前后有什么变化。当时的名称是我们对录音的初步判断，具体哪一句真的需要修，仍要逐段确认。

我们先试了现成的处理方法。拿 F2 来说，就是让程序找出音高，再按照一定规则修正。有些地方得到了改善，也遇到过配错参考音、唱法被改掉或者出现电感的情况。F1 也经过多轮试听，声音的某些变化能听出来，但想要的发声力度还没达到。

我们还试过 NeuralSVB，这是别人做的歌声处理模型。那次用的是它已有的模型，没有用我们的录音训练或微调。结果有不满意的地方，给了我们继续研究的线索。

现在我们想试一条新的路：先围绕一个小问题准备数据，让模型学习，再用没有参与训练的录音检验它。第一步暂时讨论的是“有参考的局部跑调修正”，具体方案和分工还需要一起定。

## 模型在这里做什么

先把模型想成一个可以从例子中学习的东西。我们给它看一些例子，让它逐渐找到输入和目标之间的关系。经过训练，它会留下自己学到的参数，也就是常说的“权重”。之后我们拿新的录音试它，看看它学到的东西能不能用上。

它能学到什么，和数据的数量、内容是否合适、数据是否可靠，以及采用的模型和训练方法都有关系。我们现在的数据比较少，所以第一轮的目标是先试清楚这条路能不能走通，再根据结果决定是否补充数据。

## 数据从哪里来，为什么要整理

我们已经有一些本人清唱，也有对应歌曲的原唱人声。假设我们选择其中一句，需要先找出“我唱的这一句”和“原唱唱的同一句”。原唱可以给我们一个音高参考，再由人确认哪些地方确实需要修。

两个人唱同一句时，速度和停顿可能不同。比如同一个字，一个人唱得早一点，另一个人唱得晚一点。我们要做的“对齐”，就是找出两边相互对应的地方，让程序知道这个字应该和哪个字比较。程序可以帮忙找，人再检查拿不准的部分。原始录音会保留。

“清洗数据”就是把录音整理到适合实验的状态。例如确认歌曲和唱的内容是否对应，记录哪段可以用、哪段有明显问题，以及参考位置是否找对。清洗的具体做法要看数据实际情况。

“切片”就是从较长的录音中取出一小段，例如取完整的一句。这样更容易检查这一句和参考是否对应，也方便模型分段学习。一个字前后往往还有滑音和停顿，所以片段多长要结合实际内容决定。整段原录音仍会留下。

## 一轮训练大概是什么样

1. **先选问题。** 找几句真正想修音的地方，也保留一些唱得准或有意滑音的例子，让我们检查模型是否会乱改。
2. **整理例子。** 找到本人录音和参考中对应的位置，核对内容，记录每一段该用于训练还是后面的检验。
3. **开始训练。** 把准备好的例子交给选定的模型学习，保存训练结果。具体选哪个模型、从头训练还是在现有模型上继续学习，等数据看清楚后再定。
4. **听新的录音。** 留一些没参与训练的录音做测试，比较处理前后有没有修准，声音和唱法是否自然。有参考的方案，测试时也需要对应的参考。
5. **根据结果调整。** 如果修错了，回头检查是不是参考配错、数据标错，或者模型学得不够好。把问题和尝试记下来，再决定下一步。

切出更多片段可以方便学习和检查，但同一段录音切成很多份，仍然来自同一次演唱。测试要尽量留出独立录音，才能更清楚地看模型遇到新情况时的表现。

## 接下来先做什么

以下是目前讨论的待办，具体分工和训练方案还要一起商量。

- [ ] 盘点已有的跑调录音和对应原唱，先选一首歌。
- [ ] 找出几处需要修的唱句，核对原唱中对应的片段，也留意唱准和有意滑音的地方。
- [ ] 整理第一批片段，留出未参与训练的录音用于测试，原始录音保留。
- [ ] 结合数据情况，确定小模型和训练方式，尝试训练并保存结果。
- [ ] 用新录音和对应参考测试，试听修音效果，记录反馈，再决定如何调整。

## 我们两个人可以怎么参与

我们可以一起选一个具体问题，再一起看结果。比如挑一处明显跑调的唱句，确认对应的原唱片段，讨论这一段应该修到什么程度。接着一人可以尝试整理和核对数据，另一人研究训练过程，之后互相讲清楚做了什么、遇到了什么问题。具体分工由我们商量。

这过程中会接触音频数据、Python 程序、模型训练、实验对比和问题排查。每次都围绕一个实际问题做出结果，再讨论下一步。遇到不懂的地方可以先问“这个东西在我们这一步起什么作用”，用到哪里就学到哪里。

我们最后要看的，是处理后的音频有没有达到想要的效果。程序跑通、训练完成或测量数字变化，都是过程中的信息，听感还需要我们自己判断。
