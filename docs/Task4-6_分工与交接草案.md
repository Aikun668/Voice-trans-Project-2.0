## Task 4：整理样本与清洗方案

**目标：**整理本人音频、原唱参考、时间和人工标记，让可靠材料与未确认材料能区分。

| 谁 | 做什么 | 交付 |
|---|---|---|
| Agent | 整理样本清单：来源、哈希、歌曲和版本、起止时间与时间基准、实际唱词、参考位置、人工标注和确认状态；提出清洗及排除规则。保留原始文件和已有结果。 | 清单、清洗方案、待确认／排除清单，以及数据与证据路径。 |
| 徐同学（待确认） | 独立抽查一小批样本的来源、时间顺序、同字和标记；记录错误和判断依据。 | 抽查记录与待解决问题。 |
| Jade | 对确实无法由程序或徐同学判断的唱法、歌词作集中确认；已确认的不重复询问。 | 少量确认结果或“拿不准”。 |

验收：清单能追溯到原文件；已确认、候选和不可用分开；缺字、零时长、时间漂移及歌词差异不强配。试听确认了某个整体片段，不自动确认其中每个字的边界。清洗方案和数据能否用于具体模型，仍要按 Task 6 的输入要求复核。

## Task 5：划分训练和独立测试素材

**目标：**确定训练、验证（如方案需要）和测试范围，让测试能反映模型遇到新歌的情况。

| 谁 | 做什么 | 交付 |
|---|---|---|
| Agent | 根据清单提出按歌曲划分方案，统计每组歌曲、录音版本和候选有效时长；检查同歌的版本、切片和重复来源是否跨组。 | 划分表、时长统计、检查结果及不足。 |
| 徐同学（待确认） | 独立检查划分表与文件归属，提出数据泄漏或数据太少的问题。 | 简短复核记录。 |
| Jade | 与徐同学看划分方案，决定首轮留哪首歌测试。 | 对首轮划分的决定。 |

原则：同一首歌的不同版本和切片放在同一组，尽量留一首歌独立测试；三首样本较少，具体分配和数据是否足够都待核实。参考音频的使用方式随最终方案记录，不能把训练时见过的目标材料冒充独立测试。

## Task 6：调研并选择训练或微调方案

**目标：**结合数据、许可和算力，选一个能够验证“有参考的局部跑调修正”的小规模方案；不预设现有模型一定适用。

| 谁 | 做什么 | 交付 |
|---|---|---|
| Agent | 优先调查可复用方案；记录项目地址、版本、许可证、接口、输入输出、数据及算力需求、安装与运行成本、适配工作、局限；核对本机资源并整理对比。 | 可比较的方案表、推荐理由和最小验证步骤。 |
| 徐同学（待确认） | 独立阅读至少一个候选方案，检查输入输出、训练数据需求与实际可运行性；记录不确定点。 | 候选方案简报和问题清单。 |
| Jade | 看通俗对比，与徐同学共同决定首个试验方案；有需要时确认算力和投入约束。 | 首轮选择与必要约束。 |

验收：至少有可核实来源与许可证的候选对比，明确当前素材能否满足输入条件和未满足项；只有方案选定、数据划分与所需输入准备好后，才进入训练。复用优先，不能把参考人声直接当成无误的目标音高。
