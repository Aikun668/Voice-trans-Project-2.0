# F1 模块 A、B、C、D 目标与待执行计划

状态：**待逐项推进**。本文记录职责、验收方向和后续任务；未打勾的事项均未完成。既有 V0 已实现部分工程流程，不代表各模块已经达到本文的验收目标。

日期：2026-10-27

## 一、F1 要达到什么结果

让处理后的清唱在正常音量下听起来更悦耳、更愿意继续听，同时仍然明显是演唱者本人，歌词、情绪和轻重变化都保留。

F1 有两个需要兼顾的目标：

1. **处理明确问题**：当确有刺耳、齿音或大小声突兀等问题时，针对问题改善，其他部分尽量保持自然。
2. **改善整体听感**：原音没有明显缺陷时，也可以探索让声音更饱满、柔和、悦耳；具体优先方向和样例需先与 Jade 对齐，不能把“没有明显缺陷”直接等同于“不需要美化”。

边界：离线处理原始清唱 WAV；不训练模型、不寻找预训练权重、不重新合成人声；不主动修改音高和节奏，不做 F2 修音、降噪、人声分离、混响、伴奏或实时部署。保留原音和旧实验，新增实验使用新目录。

**最终听感好，不等于指标变化或技术检查通过。** 工程检查通过只说明已检查的技术条件达标；主观效果由 Jade 试听确认。

## 二、目前在哪里

现有 V0 已能执行音频分析、压缩决策、DSP 输出和等响 A/B/C 对照，但目前只自动决定温和压缩；自动 EQ 关闭，去齿音执行器未实现。两条本人录音的输出通过既有工程检查。

Jade 对《是谁在唱歌》的等响原音 A、固定压缩 B、自适应压缩 C 反馈：**“这三个 ABC 版本的都好像没什么差别。”** 本轮听感记为 **收益不明确**，不作为 F1 美化通过或正向基准。已核对磁盘文件不同、响度匹配；实际播放器打开的文件和播放路径仍需视后续需要核验。上一轮的技术报告中保留当时状态；本文补充最新听感反馈，不改写历史产物。

相关记录：[V0 实现和运行说明](../../../f1_adaptive_v0/README.md)、[旧路线收尾](../../F1_REBASE_2026-10-27.md)、[既有听感验收标准](../../F1_LISTENING_ACCEPTANCE.md)。

## 三、模块 A：音频特征分析

**负责什么：** 读取原始清唱，描述哪些片段较响或较轻、不同频段能量如何变化、哪些位置有高频突发等，输出 `features.json`。提供可定位的线索和不确定说明，供 B 决策。

**什么结果算好：**

- 对选定录音能够稳定描述音量分布、峰值、动态变化和频段分布，并给出相关片段的时间位置。
- 前后添加静音或对整体施加固定增益时，相关特征按预期变化，不把静音误判为演唱动态；以已知信号和本人录音分别验证。
- 不同输入的差异能够反映在结果里；缺少足够证据时明确写 `unknown` 或等价的不确定状态。
- 把“测量事实”和“可能的听感问题”分开：频谱高不等于刺耳，高频突发不自动等于齿音过重。
- 活动片段门槛被标为启发式方法，不宣称已经准确识别全部演唱、气声或尾音。

**待办：**

- [x] 选取少量代表性本人录音和可定位的片段，登记素材、时间、预期观察项。
- [ ] 核对音量、频段及高频候选时间位置；分别检查静音、整体音量变化和短录音的影响。
- [ ] 汇报哪些特征可供 B 使用、哪些仍不可靠，并附实际证据和局限。
- [ ] 与 Jade 对齐 A 的结果与下一模块入口；确认后再推进 B 的调整。

**A阶段进展（2026-10-27，尚未整体验收）：** 已核查本人SHIGE正常/中度跑调及网络《告白气球》，修正数字静音边界；进一步采用峰值相对RMS门槛，三条在−65dBFS模拟背景声前后缀下动态统计稳定。门槛以下的非零声音现列为unknown，未完成人声/噪声识别；门槛附近背景声仍会明显干扰，真实片段和高频候选仍待核对。详见[本轮报告](../../../experiments/F1_module_a_lowlevel_2026-10-27_v001/低电平分析修正报告.md)。没有进入B/C/D调整。

**A阶段进展（2026-10-28，仍未整体验收）：** Jade 确认 SHIGE 正常版约 5.74～6.29 秒为正常停顿；A 将其列为低电平 unknown，内存中只将该区域置零的对照表明此例对动态统计的影响约 −0.011 dB。A 尚不能自动识别停顿，B 也不消费该标注。[停顿样例核查](../../../experiments/F1_module_a_pause_review_2026-10-28_v001/停顿样例核查.md)另准备一条本人录音中的低电平候选待 Jade 判断，不能将这一处推断到其他录音。

**A阶段补充（2026-10-29）：** Jade 确认中度跑调版约 11.03～11.23 秒附近为“明显的换气”。A 将其列为低电平 unknown，并未自动识别换气；不推定所有 unknown 都是停顿或换气。目前仍缺人工确认的轻唱/歌词尾音样例，详见同一[样例核查](../../../experiments/F1_module_a_pause_review_2026-10-28_v001/停顿样例核查.md)。

**参考：** [librosa RMS 接口](https://librosa.org/doc/0.11.0/generated/librosa.feature.rms.html)；[EBU R 128 响度建议](https://tech.ebu.ch/files/live/sites/tech/files/shared/r/r128v5_0.pdf)。EBU 对短于一分钟内容不建议使用其定义的响度范围（LRA）作为可靠评价；项目内短时 RMS 范围是不同指标，也不能直接当成听感好坏。

## 四、模块 B：自适应规则决策

**负责什么：** 根据 A 的特征和可确认的目标，决定哪些处理开启、跳过或标记不确定，生成包含参数、理由和未处理原因的 `decision.json`。决策不得依赖文件名或人为指定的素材类别。

**什么结果算好：**

- 每项处理都有明确触发条件和安全边界；不确定或无需处理时能够诚实旁路，并说明原因。
- 同一录音只改变整体输入电平时，不应无理由改变处理方向；不同素材的决定应由其特征与目标支持。
- 能展示“测量 → 判断 → 参数”的可追溯关系，便于复现和后续替换决策方式。
- 区分明确缺陷的修正与整体悦耳度改善：后者需要已对齐的风格目标或参考，不因原音正常就默认无美化需求。
- 规则可在“应处理、应旁路、不确定”的已登记样例上接受检查；不以不同文件得出不同参数本身作为成功。

**待办：**

- [ ] 基于 A 已核实的特征，整理应处理、旁路、不确定的样例和预期决定。
- [ ] 核验当前压缩规则的触发理由、参数边界与输入电平变化的影响；将未经听感校准的阈值明确标为实验值。
- [ ] 与 Jade 对齐正常录音的首个整体美化方向，例如更饱满或更柔和；不替 Jade 预选听感目标。
- [ ] 针对已确认目标研究决策所需的参考和依据，记录仍无法自动判断的情况。
- [ ] 汇报具体决策结果与失败案例；确认后再推进 C 的相应处理。

**参考：** [自动混音的语义与决策研究](https://www.arpjournal.com/asarpwp/a-semantic-approach-to-autonomous-mixing/)。该研究讨论自动混音与音频特征，并非已证明适用于本项目的单轨清唱美化，不直接照搬参数。

## 五、模块 C：最小 DSP 执行器

**负责什么：** 使用成熟效果器按 B 的决定处理音频，支持关闭单个效果器，导出完整 WAV；对处理量、音质风险和原音保留进行检查。

**什么结果算好：**

- 按决策执行且参数有界，旁路时确实不进行该项效果；输出与输入时间对齐、时长和样本数符合约定。
- 没有削波、异常静音、明显跳变、掉字或尾音损失；经既有质量检查，保留已知诊断的适用范围与不足。
- 效果针对选定目标；仍像本人，歌词清晰、轻重和情绪保留，没有不能接受的闷糊、抽吸、发毛或失真。
- 每轮只验证一个听感假设，优先一条本人录音、最多两个候选；未经认可的效果不提前叠加。
- EQ、压缩和齿音控制分别说明已实现与已验证的边界；固定高频衰减不冒充动态去齿音。

**待办：**

- [ ] 确认本轮唯一听感目标、来源片段、期望变化和否决副作用。
- [ ] 查成熟效果器的接口、使用方式和适配边界；优先复用现有依赖，不从零重写基础算法。
- [ ] 单项生成最多两个候选，保存参数及复现信息；检查原音哈希、完整解码、规格、样本数、削波、真峰值、响度差、异常静音/跳变与粗略音高。
- [ ] 工程失败先定位，不能放宽门槛凑通过；工程通过后交 D 试听。
- [ ] 有一条本人录音明确更好且自然时，保存设置，并用另一条本人录音复验，再讨论组合。

**参考：** [Spotify Pedalboard 官方接口](https://spotify.github.io/pedalboard/reference/pedalboard.html)；[动态去齿音机制参考](https://github.com/audiojs/dynamics)。后者仅作机制参考，尚未核实 Python 接入、许可证适配及本人歌声效果。

## 六、模块 D：对照实验与听感验收

**负责什么：** 组织可复现、公平且目标明确的原音与处理版对照，记录工程检查和 Jade 试听结果，为下一步提供依据。D 的验收要求从每轮开始就参与，而不是等所有模块做完才考虑。

**什么结果算好：**

- 对照音频来自同一素材，时间对齐、完整可播放、试听响度尽量匹配；固定播放器音量，记录文件和参数。
- 试听前讲清本轮只想改善什么、听哪一段、不接受什么副作用；不要求 Jade 理解频率或专业参数。
- Jade 正常听一两遍可感知目标改善、愿意选择处理版，且没有不可接受副作用：三项同时满足，才记 **本条素材暂通过**。
- 换另一条本人录音复验后，才考虑保留或组合；两次技术通过都不能代替听感通过。
- 听不出区别或非常认真才辨认出一点差异，记 **收益不明确**；不把参数变化或音量更大当作改善。

**待办：**

- [ ] 在每轮处理前登记素材、来源区间、原音问题或美化目标、预期变化及否决副作用。
- [ ] 对照文件和播放路径，检查时长、完整解码、响度和真峰值；明确标注原音和候选。
- [ ] 记录 Jade 原话、偏好、是否有副作用及其时间点；Agent 无直接听音能力时明确说明。
- [ ] 对“听不出区别”先核验文件、播放路径和响度；只有有依据时才做最多一次针对性修订，仍无收益则暂停候选。
- [ ] 对明确更好且自然的单素材结果，保存设置并安排另一条本人录音复验。

**参考：** [ITU-R BS.1534 主观音频评估](https://www.itu.int/rec/R-REC-BS.1534/en)。借鉴受控对照原则；项目日常试听不声称符合完整标准，也不要求盲听。

## 七、逐项推进与汇报方式

1. **先 A**：核对分析结果与真实片段，汇报可靠项和不可靠项。
2. **再 B**：基于可信特征和已对齐目标检查决策，汇报处理、旁路和不确定案例。
3. **再 C**：围绕一个听感目标做单效果小样，先完成工程检查。
4. **由 D 验收**：交 Jade 听原音与候选，记录反馈；符合单素材条件后再换本人录音复验。

每完成一个模块，向 Jade 简洁汇报：**负责什么、实际做到什么、对照什么参考、怎么验证、还差什么、下一步建议**。先对齐结果，再进入下一模块；不把计划当成已完成，也不把一次技术通过当作听感验收。

当前需要后续对齐：正常录音的第一个整体美化方向是更饱满、更柔和，还是 Jade 提出的其他描述；当前不预设答案。
