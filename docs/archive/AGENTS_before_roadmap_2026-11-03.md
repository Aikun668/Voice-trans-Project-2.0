# F1 功能适配与试听规则

## 当前基线（2026-10-27）

- 当前主线为 f1_adaptive_v0/；入口与限制见其README，旧路线收尾见 docs/F1_REBASE_2026-10-27.md。
- 用户已授权特征分析→规则参数JSON→成熟DSP的独立V0；不训练、不寻找预训练权重、不重建人声。
- V0当前仅自动决策温和压缩；自动EQ关闭、去齿音未实现。特征风险不等于主观缺陷。
- 原始录音/旧实验保留，不覆盖；输出使用新目录，技术与听感验收继续分开。

## 任务边界

- 本项目先做 F1：改善饱满度、柔和度、悦耳度、刺耳、齿音和大小声问题，保留本人音色与情感。
- F1 不主动修改音高或节奏；降噪、人声分离、混响、伴奏合成不在当前需求内。
- 用户在讨论方案时先分析；明确要求执行时完成该次已授权的小任务。

## 功能优先、复用优先

1. 先写清缺失功能和可听见的目标，再查参考项目及其具体模块。
2. 优先调用已有模块、模型或插件，不从零重写音频算法。不为更换工具而更换工具。
3. 不整仓照搬。允许输入电平、格式、参数范围、原音混合、输出校准等必要适配；说明适配理由。
4. 记录项目地址、具体接口、版本、许可证、官方流程、当前复用范围和未验证事项。
5. 一个项目可以覆盖多个维度；一个维度也可以在候选不适用后更换项目。

## 小步交付

- 每轮只验证一个功能假设。先交付独立效果，不提前叠加未经认可的模块。
- 每轮优先一条本人录音，最多两个候选；原音匹配响度，正常标注名称，不要求盲听。
- 完整 WAV 保留时长；试听短句另存，明确其拼接顺序和来源区间。
- 原始素材、旧实验和他人未提交改动全部保留，新实验使用新目录。不得自动覆盖或清理。
- 依赖隔离安装，禁止因试验改坏现有 Python 环境；无用户要求不推送 Git。

## 两层验收

- 听感标准统一见 docs/F1_LISTENING_ACCEPTANCE.md。每轮先登记原音问题、片段、预期可听变化和否决副作用，再生成音频。
- 项目/插件有某项能力，不代表当前素材需要它。原音无相应问题时标记不适用；问题未确认时先对齐样例，不继续盲试。
- 工程检查：原音哈希、完整解码、规格/样本数、削波、真峰值、响度差、异常静音/跳变及粗略音高诊断。
- 调整工程拦截前先调查原因，不能为了交付而放宽阈值；功能特意产生的新谐波与损坏要区分。
- 技术通过只记 technical_pass；听感始终记 pending_jade，直到 Jade 明确反馈。
- Agent 无直接听音能力时必须明示；不能把测量变化、通过测试说成变好听。

## 听感反馈后的动作

- 明确更好且自然：标记“单素材暂通过”，保存设置，再用另一条本人录音复验；复验后才考虑组合。
- 更好但有副作用：保留正向基准，只调整同一模块的一个控制量，最多一次有依据的修订。
- 听得出变化但不更好：不把变化当成功；旁路该模块，最多一次针对问题的修订。
- 听不出区别：先核验实际文件、播放路径和响度，再允许一次有依据的强度修订；仍无收益就暂停该候选。
- 明显更差、失真、像换人或工程拦截失败：不进入组合，先定位；无法低成本修复就更换候选。
- 单个功能最多“初测 + 一次针对性修订”，随后总结适用性或更换机制，不无限试参。
- 保存用户原话、素材、偏好版本、副作用时间点和下一动作；不能代替用户填写通过。
- 正常试听可偏好处理版、目标改善可感知、无不可接受副作用，三项同时满足才单素材暂通过。
- 有变化不等于更好；非常认真才一点差别记收益不明确。没有正向基准且强档有明显副作用，可以直接暂停候选，无须用完修订次数。
